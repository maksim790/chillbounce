# Shell и wallet: технический frontend — дизайн v1

Status: approved — дизайн v1 согласован пользователем 2026-11-12 ответом «да.» на вопрос «Подтверждаешь этот дизайн?». Запись согласования: 2026-11-12T16:03:18Z.

Источник и критерии: [тикет](../../Tasks/frontend-shell-wallet.md). Это небольшой инфраструктурный этап: два приложения и один federation-контракт, без бизнес-интерфейса. Никакие приложения или зависимости в ходе подготовки не создаются.

## Подход и альтернативы

Предложение агента — @module-federation/vite вместе с React и Vite. Плагин поддерживает host/remotes и shared dependencies; его текущий peer range включает Vite 8. Конкретные stable-версии с peerDependencies нужно перепроверить перед реализацией, включая совместимость с TypeScript 6.0.3 и ESLint 10. Официальный Vite template не копируется целиком: текущая документация уже показывает TS 7, тогда как используемый линтер требует TS <6.1.

Реальная альтернатива — @originjs/vite-plugin-federation: привычная модель exposes/remotes, но документация требует build remote даже в dev; это добавляет build/watch/serve цикл. Для нового Vite-проекта рекомендуем @module-federation/vite. Цена решения — зависимость от конкретного плагина и его совместимости; работу dev и preview нужно проверять в браузере, а не считать доказанной документацией. Полноценный HMR через federation не обещается без проверки выбранных версий.

## Ответственность и интерфейс

- apps/shell владеет страницей-контейнером, загрузкой wallet, loading UI и error boundary. Shell не владеет данными/операциями кошелька, которых в этом этапе нет.
- apps/wallet владеет минимальным техническим компонентом Wallet. Public expose `./Wallet`, consumption `wallet/Wallet`, default export React-компонента без props. Никаких shared stores, событий, auth/session contracts или общих доменных пакетов сейчас нет.
- Standalone entry wallet создаёт React root и рендерит этот компонент. Экспортируемый компонент root не создаёт, DOM контейнер не ищет и глобальную страницу не перенастраивает.
- Shell загружает компонент лениво через federation, с Suspense/loading и error boundary. Тип модуля в shell описывается узко, без any и без зависимости от исходного пути remote. Генерация/доставка типов не нужна для интерфейса без props; при его развитии контракт потребуется пересмотреть.
- React и react-dom согласованных версий объявляются singleton с проверкой используемых subpath imports (JSX runtime/client). Одинаковая версия пакетов сама по себе не доказывает единую runtime-копию: браузерная интеракция должна работать без invalid hook call.

## Минимальный экран

Shell: заголовок Chillbounce, подпись технического host и область wallet. Wallet: название модуля и одна локальная кнопка/счётчик для проверки React state. Это технический индикатор, без баланса, активов, транзакций, финансовых моков и визуального дизайн-системного решения. Точный текст и нейтральное оформление остаются обычными деталями реализации.

В согласованном объёме нет маршрутизации и router dependency, меню продукта, auth и shared UI. Страница сразу показывает область wallet. Это сужение ранней идеи «базовой навигации» до минимального проверяемого экрана входит в согласованный дизайн v1.

## Запуск и конфигурация

Два package scripts dev и root параллельный pnpm запуск; сборки и preview отдельно и совместно. Предлагаемые локальные порты shell 5173, wallet 5174 с strictPort; preview может использовать те же порты, когда dev остановлен. Не запускать dev и preview одновременно на одной паре портов. Сервисы локальны; развертывание не настраивается.

Remote URL — публичная frontend-конфигурация (например VITE_WALLET_REMOTE_URL) с документированным локальным значением. В production URL не должен безусловно указывать на localhost. Способ задания URL при build/preview, путь remote entry и допустимые origins фиксируются в implementation plan по выбранной версии плагина. VITE-переменные публичны, секретов в них нет. Не использовать server.cors true без необходимости: достаточно нужного локального origin для связи приложений.

При первой загрузке wallet недоступен/возвращает ошибку: shell остаётся работоспособным и показывает fallback. После восстановления и полной перезагрузки wallet загружается. Уже загруженный модуль не обязан исчезать при выключении сервера; проверка отказа выполняется на свежей странице. Автоматические retries, offline mode и production observability не входят в этап.

## Конфигурации и зависимости

TS base сохраняется runtime-neutral. У каждого приложения frontend tsconfig с DOM/JSX/moduleResolution bundler; Vite config получает отдельный Node tsconfig. Root typecheck запускает scripts обоих пакетов. Общее ESLint расширяется необходимыми React Hooks/Refresh правилами по совместимости выбранных версий; добавлять router/state/UI frameworks заранее не требуется. Вся установка использует существующий root pnpm-lock.yaml, стиль Prettier с табуляцией сохраняется.

## Проверки и ограничения

Планируются lint, format:check, typecheck, build обоих пакетов и воспроизводимая установка. После согласования архитектуры пользователь уточнил: «не надо запускать playwright тесты». В плане v2 тестовая инфраструктура исключена, предложены CLI и ручные проверки loading/error boundary без Playwright. Browser smoke: standalone wallet, shell+wallet в dev, оба preview после сборки, React state в remote, отсутствующий remote при свежем открытии, восстановление с перезагрузкой и занятой порт. Сборка без browser smoke не доказывает федерацию. Архитектура и минимальный UI не меняются; новая проверочная часть проходит финальный review плана.

Точные версии, scripts и ручные проверки детализируются в [implementation plan v2](../plans/2026-11-12-frontend-shell-wallet.md), который согласуется отдельно. Команды реализации и browser checks ещё не запускались.
