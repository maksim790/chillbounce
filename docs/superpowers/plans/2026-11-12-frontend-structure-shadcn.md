## Ограничения

- Только документация. Не переносить исходники, не создавать папки приложений/пакетов, не менять зависимости, конфигурации или lockfile.
- Цель: apps/frontend/shell, wallet, будущие remotes и packages/ui; рядом apps/api для будущего NestJS. Корневые pnpm/lockfile и общие инструменты сохраняются.
- Внутри frontend app — app/pages/features/shared по мере необходимости; бизнес-обязанности Shell/Wallet и backend не пересматриваются.
- Общие исходники UI располагаются в apps/frontend/packages/ui. Доставка через Shell, локальная сборка потребителями, aliases, версии и CSS pipeline пока открыты.
- После исследования: не требовать barrel/index.ts для каждой feature; сохранить узкие точки входа. В документе отметить будущую проверку минимальных Button/Dialog, темы и CSS в standalone/composition, без выполнения этих проверок сейчас.
- Не запускать приложения, browser checks, lint/typecheck/build для этого документационного изменения. Не вводить новый runner или автоматическую проверку импортов.

## Review Focus

1. Целевые вложенные пути не названы существующими; текущие ссылки на apps/shell и apps/wallet остаются корректными.
2. Владение исходниками UI не смешано с runtime-sharing через Shell; отсутствие дубликатов кода не обещается.
3. В UI-пакет не попали бизнес-данные, auth или API; межприложенные импорты внутренних исходников запрещены.
4. Открытые crypto/auth/router/API вопросы и standalone remote не потеряны при смене структуры.
5. У будущего переноса отмечены workspace discovery, TS/ESLint/Vite paths и ссылки; документационный этап не выдаётся за миграцию.
