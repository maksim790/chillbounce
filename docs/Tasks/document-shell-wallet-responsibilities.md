## Объём и критерии приёмки

1. В Frontend описаны будущие Shell (оболочка, общий доступ, навигация, интеграция) и Wallet (активы, балансы, пополнение, перевод, вывод, история), согласно согласованному дизайну. Обязанности не дублируются между модулями.
2. Описаны границы с backend: frontend не авторитетен для балансов, прав и статусов; ключи/ledger/подпись остаются backend-задачами. Не придумываются комиссии, лимиты, способ авторизации и финансовые инварианты сверх брифа.
3. Отмечены границы сессии, навигации и отказов: Shell сохраняет оболочку при недоступном Wallet; Wallet отвечает за состояния своих сценариев; конкретные router/auth/API контракты остаются отдельными будущими решениями. Текущий экспорт без props не меняется.
4. Назначение crypto явно открыто, admin сохраняется как будущий мониторинг. Система, продукт, решения, roadmap/open questions, Home и карта источников согласованы с основным описанием без дублирования и без выдачи будущего за реализованное.
5. Изменены только документы. Нет разработки интерфейсов, исходников, зависимостей, API или запуска приложений/браузерных тестов. Документы и относительные ссылки проверены по DoD; история решений сохранена.
