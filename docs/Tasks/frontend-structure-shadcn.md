## Цель и запрос

Пользователь просит определить структуру frontend, соблюдаемую Shell и всеми remotes, и явно выбирает shadcn/ui. На предложение лёгкой структуры по сценариям, общего UI-пакета и документационного этапа ответил «давай». Результат этой задачи — стандарт в базе знаний для будущей реализации; установка UI и реорганизация кода не входят.

## Основания

- [Frontend](../02-System/Frontend.md) и [тикет обязанностей](document-shell-wallet-responsibilities.md) задают Shell/Wallet, backend-границу и открытые auth/router/API решения.
- [Исходники Shell](../../apps/shell/src/App.tsx), [Wallet](../../apps/wallet/src/Wallet.tsx), manifests и Vite configs подтверждают техническую federation-связку и плоский src. Сейчас packages/ui, shadcn/ui и Tailwind отсутствуют.
- [pnpm workspace](../../pnpm-workspace.yaml) уже включает apps/* и packages/*; новый task runner не нужен.
- [Официальная monorepo-документация shadcn/ui](https://ui.shadcn.com/docs/monorepo), полученная через Context7, описывает shared UI package, aliases и package exports. Это источник механизма, не пользовательского выбора архитектуры.
- При подготовке рабочее дерево чистое; после fetch dev совпадает с origin/dev. Создана feature/frontend-structure-shadcn. Источник новых требований — текущая беседа, публичный URL недоступен.

## Объём и критерии приёмки

1. Описана целевая группировка apps/frontend (Shell, remotes и frontend-пакеты) рядом с будущим apps/api; корневой pnpm/lockfile сохраняется. Есть каноническое описание общего стандарта для каждого frontend app: app/pages/features/shared и технические entry points. Указано назначение папок, создание по необходимости и размещение кода рядом со сценарием; нет требования создавать пустые слои.
2. Определены направление зависимостей, узкие публичные exports сценариев, запрет импортов внутренних файлов соседних apps и правила использования существующей federation-границы. Даны конкретные примеры размещения и допустимых/недопустимых импортов без изменения runtime-контракта.
3. Описан будущий apps/frontend/packages/ui как владелец общих shadcn-компонентов, UI-хуков, утилит и токенов, без бизнес-логики и зависимости от apps. Различены общий UI и локальный shared/ui; зафиксированы владельцы темы и требования к стилям для standalone и composition, без заявления о проверенной CSS-изоляции.
4. Согласованы Frontend, Tooling, решения, roadmap/open questions, Home и карта источников. Отдельно обозначены будущий стандарт, текущая реализация и отложенные детали внедрения. Ранее утверждённые обязанности Shell/Wallet и backend не пересматриваются.
5. Изменены только документы; исходники, зависимости, конфигурации и файловая структура apps/packages сохранены. Локальные ссылки, форматирование и содержательное соответствие критериям проверены по [DoD](../05-Engineering/Testing-Strategy.md); приложения и browser checks не запускаются.
