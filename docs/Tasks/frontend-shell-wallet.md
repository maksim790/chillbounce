## Объём и ограничения

Два реальных приложения apps/shell и apps/wallet, их отдельный и совместный локальный запуск, сборка и preview, наследуемые TS/ESLint настройки, минимальные технические экраны и обработка сбоя remote. Версии стабильные и совместимые с текущим Node/pnpm/TypeScript; не копировать новые defaults TS 7 вопреки текущей совместимости линтера.

Не входят полноценные интерфейсы, баланс/транзакции/финансовая логика, backend/RPC, авторизация, wallet connection, UI kit, packages/ui/contracts/config, crypto/admin remotes, deployment и Nx. Не добавлять демонстрационные финансовые данные. Маршрутизация не включена в согласованный дизайн: достаточно одного технического экрана shell с областью wallet. По последующему уточнению пользователя «не надо запускать playwright тесты» Playwright не запускается; в плане v2 также исключены его установка, test suites/configs, fixtures и test scripts. Вместо добавления другого runner предложены CLI и ручные проверки в браузере без Playwright.

## Критерии приёмки для финального review

1. Shell и wallet — отдельные private workspace packages на React/TypeScript/Vite. Оба запускаются самостоятельно; root pnpm-команда поднимает оба. Для занятого порта запуск завершается понятной ошибкой, не меняет порт незаметно.
2. Shell загружает wallet через Module Federation в браузере; прямого импорта исходников wallet через workspace/path alias нет. Wallet использует один и тот же компонент при самостоятельном запуске и внутри shell.
3. Публичный модуль — wallet/Wallet с default React-компонентом без props; он не создаёт собственный React root. React и react-dom совместимы и shared singleton; проверяется также React JSX runtime. Минимальная локальная интеракция в wallet работает без ошибок hooks.
4. Shell показывает загрузку и понятный fallback при ошибке загрузки/рендера remote; оболочка остаётся видимой. Сценарий недоступности проверяется свежим открытием shell при остановленном wallet. После восстановления wallet и перезагрузки страницы модуль снова доступен; автоматические retries в объём не входят.
5. В dev и в build+preview связка реально работает с раздельными origins. URL remote задаётся публичной конфигурацией окружения; неправильная конфигурация не маскируется успешным экраном. Локальные значения и способ переопределения документированы без секретов.
6. TS-конфигурации приложений наследуют strict base; DOM/JSX/bundler options локальны для frontend, Node options для vite.config отделены. Root typecheck действительно проверяет оба проекта. Добавлены только необходимые React ESLint расширения, стиль Prettier сохраняется.
7. Есть реальные package scripts dev/build/preview/typecheck и root-команды совместного запуска/сборки без нового task runner. Обязательные lint/format/typecheck/build проходят; loading/fallback и реальная связка проверяются вручную в браузере без Playwright, результаты фиксируются для dev и preview. Playwright и другие test runners не добавляются; автоматические browser tests не запускаются и не объявляются пройденными.
8. README, обзор системы, Tooling, затронутые решения/roadmap и карта источников отражают фактические команды, границы и ограничения. Markdown-ссылки разрешаются; будущие бизнес-функции не описаны реализованными.
