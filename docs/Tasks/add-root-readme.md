## Цель и запрос

Создать README.md в корне Chillbounce со ссылками на файлы документации. Явное требование пользователя: «создадим README.md в корне репозитория с указанием ссылок на файлы документации». README должен стать краткой точкой входа, а подробная база знаний остаётся в docs.

## Основания и текущее состояние

- [AGENTS.md](../../AGENTS.md) задаёт назначение проекта, целевую архитектуру, правила документации и Git.
- [Home](../Home.md) — существующая навигация по vault; [продукт](../01-Product/Overview.md) — источник краткого описания Chillbounce.
- [Политика проверок](../05-Engineering/Testing-Strategy.md) требует проверки критериев и Markdown-ссылок.
- При подготовке README.md не обнаружен. Git ещё не инициализирован; подготовлен [согласованный тикет инициализации](initialize-git-repository.md). Первоначальная процессная зависимость от Git отменена последующим выбором пользователя выполнить README первым; этот тикет сам Git не инициализирует.
- В Home пока осталась исторически устаревшая фраза «Задачи разработки ещё не создавались»; при обновлении навигации нужно исправить её по фактическому состоянию на момент выполнения.

## Объём и критерии приёмки

1. В корне есть читаемый README.md на русском языке с названием Chillbounce и кратким описанием по существующим источникам. Целевая функциональность не представлена как уже реализованная.
2. README содержит обычные относительные Markdown-ссылки с понятными подписями на Home, описание продукта, текущее состояние системы, индекс решений, roadmap, открытые вопросы, политику проверок, исходный бриф, карту источников и AGENTS.md. Абсолютные локальные пути и обязательные WikiLinks не используются.
3. README не дублирует полные требования и правила, не добавляет неподтверждённые команды запуска, выбранные технологии, лицензии, бейджи или сведения о деплое.
4. В Home добавлена обратная ссылка на README и минимально исправлена устаревшая информация о наличии задач. В карте источников учтён README как навигационная страница; существующие документы сохранены на своих местах.
5. Все локальные ссылки README и затронутого vault разрешаются; проверено соответствие текстов источникам. Если README уже появился к началу выполнения, сначала изучить его и согласовать конфликтующий объём, не перезаписывать чужую работу.

Архитектура приложения, API, безопасность и runtime-поведение не меняются. Отдельные дизайн и implementation plan для этой локальной документационной задачи не требуются. В этой задаче пользователь выбрал выполнение до настройки Git: feature-ветка и отдельный коммит сейчас не создаются, изменения можно включить в первый коммит при последующей инициализации. Это локальное исключение не меняет общие правила AGENTS.md.

## План проверки

- Сопоставить README с перечисленными критериями, Home, описанием продукта и текущим состоянием проекта.
- Проверить все ссылки корневого README отдельно: validator из политики проверок обходит docs и сам по себе не подтверждает корректность ссылок из корневого README.
- Запустить read-only validator vault по команде из политики проверок; сравнить изменённые файлы с сохранённым до правок состоянием, поскольку Git diff пока недоступен. Проверка коммита не применяется к выбранному выполнению до настройки Git.
- Сборка и тесты приложения неприменимы к этой документационной задаче. При подготовке проверяется только тикет, результат реализации ещё отсутствует.
