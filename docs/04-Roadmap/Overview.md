# Запланированный объём

Источник: [требования пользователя](../06-Sources/Project-Brief.md). Все перечисленное заявлено пользователем и пока не реализовано в проверенном каталоге. Приоритеты, релизы, этапы, сроки и порядок выполнения не согласованы. Эта страница отражает объём намерений, а не план исполнения задач.

## Пользовательские возможности

1. Регистрация и авторизация.
2. Кошельки с ETH, тестовыми токенами, доступным и зарезервированным балансом.
3. Адреса пополнения, обнаружение и автоматическое зачисление депозитов Sepolia.
4. Внутренние переводы между пользователями без блокчейна.
5. Вывод тестовых активов на внешние Ethereum-адреса.
6. История финансовых операций со статусами и деталями.
7. Административный мониторинг пользователей, кошельков, операций и ошибок.

Подробности: [продукт](../01-Product/Overview.md).

## Внутренние механизмы

Double-entry ledger, blockchain integration, обработка операций, защита ключей, контроль балансов, предотвращение двойных списаний и reconciliation входят в заявленный объём. Конкретные механизмы ещё предстоит определить.

## Архитектурные ограничения

Монорепозиторий, микрофронтенды с Module Federation и backend-монолит NestJS зафиксированы в [индексе решений](../03-Decisions/Decision-Index.md).

## Инфраструктура разработки

По последующему [тикету monorepo](../Tasks/initialize-monorepo.md) настроена основа pnpm Workspaces, TypeScript, ESLint и Prettier без Nx. По [frontend-тикету](../Tasks/frontend-shell-wallet.md) добавлены технические shell и wallet с Module Federation, локальным счётчиком и обработкой сбоя remote. Это не реализация пользовательских возможностей выше. Crypto/admin, api (NestJS), worker и packages/ui, contracts, config остаются будущими задачами; их исходников нет.
